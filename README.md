Lucky-Reels

1. تعريف المشروع

Lucky-Reels هو مشروع لعبة Slots تعمل عبر الويب، تتكون من ثلاث بكرات، مع نظام رموز ومكافآت ومضاعفات، وواجهة متوافقة مع الهواتف.

يُبنى المشروع من البداية بطريقة تسمح بتشغيل اللعبة بصورة مستقلة، ثم دمجها مستقبلًا داخل منصة تجمع ألعابًا متعددة، دون ربط محرك اللعبة بواجهة موقع واحدة.

2. أهداف المشروع

- تصميم لعبة Slots بثلاث بكرات.
- دعم الهواتف والشاشات الصغيرة.
- فصل واجهة اللعبة عن محرك النتائج.
- فصل الحسابات عن منطق اللعبة.
- إنشاء سجل واضح للجولات وتغييرات الرصيد.
- منع اعتماد النتائج أو تعديل الرصيد من المتصفح وحده.
- دعم الاختبارات الآلية باستخدام GitHub Actions.
- توفير واجهة تكامل موحدة للمنصات التي ستستضيف اللعبة مستقبلًا.
- الحفاظ على قابلية إضافة ألعاب أخرى دون إعادة كتابة المشروع بالكامل.
- عدم تفعيل المراهنات المالية الحقيقية قبل التحقق من المتطلبات القانونية والحصول على الموافقات اللازمة.

3. التقنيات المعتمدة

- Frontend: React + TypeScript + Vite.
- Backend: Node.js + TypeScript + Express.
- Database: PostgreSQL.
- Testing: Vitest واختبارات واجهات API.
- Repository: GitHub.
- CI: GitHub Actions.

4. معمارية المشروع

يتكون المشروع من طبقات منفصلة:

1. واجهة المستخدم: تعرض اللعبة والحساب والرصيد وسجل الجولات.
2. محرك Slots: يحدد النتائج ويطبق قواعد اللعبة على الخادم.
3. طبقة API: تربط الواجهة بالخادم من خلال عقود واضحة.
4. طبقة البيانات: تحفظ الحسابات والجولات وسجل الرصيد.
5. طبقة التكامل: تسمح لمنصة ألعاب أكبر باستضافة اللعبة مستقبلًا.

لا تُعتبر بيانات الواجهة مصدرًا موثوقًا للنتائج أو الأرصدة.

5. متطلبات التكامل المستقبلي

يجب أن تكون اللعبة قابلة للتشغيل:

- كموقع ويب مستقل.
- داخل حاوية واجهة ضمن منصة ألعاب متعددة.
- داخل WebView في تطبيق Android مستقبلي، عند استيفاء متطلبات الأمان والتوافق.
- باستخدام عقد تكامل ثابت يحدد هوية اللعبة وإصدارها وطريقة الاتصال بالخدمات.

يجب ألا تعتمد قواعد اللعبة على وجود الصفحة الرئيسية للموقع، أو على تخزين الرصيد في المتصفح.

يُحدد مصدر الحساب والرصيد من خلال الخادم، ولا يسمح للعبة المضمنة بتعديل بيانات الحساب مباشرة.

6. نطاق النسخة الأولى

- لعبة Slots بثلاث بكرات.
- واجهة متوافقة مع الهاتف.
- عرض الرصيد التجريبي.
- عرض نتيجة الجولة والمكافأة الافتراضية.
- سجل للجولات.
- واجهات حساب تجريبية.
- قاعدة بيانات منظمة.
- اختبارات محرك اللعبة وسجل الرصيد.
- فحوصات آلية عبر GitHub Actions.

يُستخدم رصيد افتراضي في بيئة التطوير والاختبار. لا تُفعّل الإيداعات أو السحوبات أو المراهنات الحقيقية قبل التحقق من قانونية النشاط والموافقات المطلوبة.
